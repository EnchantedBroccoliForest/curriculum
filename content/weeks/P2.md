# Week P2: Programming 2 and numerical Python: classes, mutability, generators; arrays, shapes, broadcasting

## Why this week

micrograd ([weeks 1–2](/week/1)) is a class whose instances carry a value, a gradient and a backward function; PyTorch ([week 3](/week/3)) is a library of array operations with the same shape rules as NumPy. This week makes both readable: objects with state, references versus copies, and $n$-dimensional arrays whose operations are defined elementwise with implicit expansion of dimensions.

## Objectives

- Write a class with a constructor, methods and overloaded operators, and explain what `self` refers to in each method.
- Predict whether a modification through one name is visible through another, for lists, tuples and integers.
- Given two array shapes, state whether they broadcast and what the result shape is, and write a matrix product as a single array expression.

## Key ideas

- A **class** is a template for values that carry data (**attributes**) and functions that act on that data (**methods**). An **instance** is one such value; `Matrix([[1,2],[3,4]])` calls the constructor `__init__`. Inside a method, `self` names the instance being operated on.
- **Operator overloading**: defining `__add__`, `__mul__`, `__matmul__` on a class makes `a + b`, `a * b`, `a @ b` call those methods. micrograd's `Value` class is exactly this, with each operator also recording how to differentiate itself.
- **Mutability and references.** A name refers to an object; assignment copies the reference, not the object. Lists and dictionaries are **mutable** (can change in place), so `ys = xs; ys.append(1)` changes what `xs` sees too. Integers, strings and tuples are **immutable**; "changing" one rebinds the name to a new object.
- A **generator** is a function containing `yield`; calling it returns an iterator that produces values lazily, one per request, keeping its local state between requests. It lets you loop over a sequence too large to hold in memory.
- An **array** (NumPy `ndarray`) is a homogeneous block of numbers with a **shape**, a tuple of dimension lengths: a vector in $\mathbb{R}^n$ has shape `(n,)`, an $m \times n$ matrix `(m, n)`, a batch of $B$ such matrices `(B, m, n)`. Indexing `A[i, j]` and slicing `A[:, j]` follow from the shape.
- **Vectorisation**: `A + B`, `A * B`, `np.exp(A)` act elementwise over the whole array in compiled code. A Python loop over elements does the same arithmetic hundreds of times slower because each iteration pays interpreter overhead.
- **Broadcasting**: two shapes are compatible if, aligning from the right, each pair of dimensions is equal or one of them is 1; the 1 is stretched. `(m, n) + (n,)` adds a row vector to every row; `(m, 1) * (1, n)` is an outer product. Reductions `A.sum(axis=0)` collapse one axis.
- `A @ B` is the matrix product $\sum_k A_{ik} B_{kj}$, requiring the inner dimensions to agree; `A * B` is the Hadamard (elementwise) product and requires broadcast-compatible shapes. Confusing them is the most common shape bug.

## Derivation or exercise, stated in full

Matrix class with operator overloading; matmul three ways, timed, ratio explained

1. **Matrix class.** Write a class `Matrix` storing an $m \times n$ array of floats as a list of lists. Implement `__add__`, `__mul__` (scalar and Hadamard), `__matmul__` (matrix product), `transpose`, and `__repr__`. Multiplying matrices of incompatible shape must raise an error naming both shapes.
2. **Matmul three ways.** For two random $n \times n$ matrices with $n = 200$ (then $n = 500$), compute the product (a) with triple nested Python loops, (b) with NumPy using one explicit loop over rows and vectorised inner work, (c) with `A @ B`. Time each with `time.perf_counter()`.
3. **Ratio explained.** Report the three timings and the ratios (a)/(c) and (b)/(c). Explain the ratios in terms of interpreter overhead per operation, number of scalar operations ($2n^3$ floating-point operations), and what work happens in compiled code versus in the Python loop. Check that all three results agree to within floating-point tolerance.

Assumptions: single machine, no GPU, NumPy installed. Do not use an AI assistant for the code.

## Common misconceptions

- `b = a` copies the list → it copies the reference; both names see the same object. Use `a.copy()` or `list(a)` for a shallow copy.
- `A * B` on two matrices is matrix multiplication → in NumPy it is elementwise; the matrix product is `A @ B` or `np.matmul`.
- A 1-D array of shape `(n,)` is a row vector → it has no row/column orientation; `(1, n)` and `(n, 1)` are the row and column matrices, and broadcasting treats them differently.
