# Week 24: Switch Transformer; DeepSeek-V3 report (MLA, MoE)

## Why this week

Mixture-of-experts is how current frontier open-weight models decouple parameter count from per-token compute, and a reader who confuses the two misreads every cost claim in a technical report. This week sets up the active-versus-total distinction that the [week 25](/week/25) budget reconstruction and the [week 27](/week/27) gate depend on.

## Objectives

- Given an MoE configuration (experts per layer, top-$k$ routing, shared experts, dense layers), compute active and total parameters and per-token FLOPs.
- Explain why a routed model needs load balancing and state one mechanism that achieves it without an auxiliary loss term.
- Explain what multi-head latent attention compresses and what it costs in compute to recover.

## Key ideas

- In a routed FFN with $E$ experts and top-$k$ routing, each token touches $k$ experts; total parameters scale with $E$, active parameters and FLOPs with $k$. A "671B" model and a "37B active" model can be the same model.
- Per-token training FLOPs follow active parameters, approximately $6 N_{\text{active}}$ per token, plus attention terms; memory for weights and optimizer state follows total parameters. Serving cost follows both: weights must be resident, compute follows active.
- Routing is a discrete choice trained through a continuous gate; without a balancing pressure, a few experts attract most tokens and the rest are undertrained. The Switch Transformer uses an auxiliary load-balancing loss; DeepSeek-V3 reports an auxiliary-loss-free strategy that adjusts a per-expert bias term used in routing only.
- Multi-head latent attention stores a low-rank latent per token in the KV cache instead of full keys and values, trading cache memory for extra projection compute at decode time.

## Common misconceptions

- "A 671B-parameter model costs 671B-parameter FLOPs per token" → Per-token compute follows active parameters; total parameters set memory.
- "Load balancing is only about training quality" → Under expert parallelism it is also about device utilisation and communication.
