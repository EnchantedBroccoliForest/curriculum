## Key ideas

- **Asymptotics**: $f(n) = O(g(n))$ means $f(n) \le c\,g(n)$ for some constant $c$ and all large $n$. It describes how running time or memory scales, ignoring constants and lower-order terms. A nested loop over $n$ items twice is $O(n^2)$; attention over a sequence of length $n$ compares every position with every other, hence $O(n^2)$ in time and memory for the score matrix.
- A **hash table** stores key-value pairs in an array indexed by a hash function $h(\text{key})$; lookup, insert and delete take constant expected time, with collisions resolved by chaining or probing. Python's `dict` and `set` are hash tables, which is why `k in d` is cheap.
- A **graph** is a set of vertices and edges; **directed** edges have an orientation. **BFS** (breadth-first search) explores by distance from a start vertex using a queue; **DFS** (depth-first search) follows one path to its end using a stack or recursion. Both run in $O(V + E)$.
- A **topological sort** of a directed acyclic graph (DAG) is an ordering of vertices in which every edge points forward. It exists iff the graph has no cycle. A computation graph is a DAG from inputs to outputs; evaluating it in topological order is the forward pass, and visiting the reverse of that order is the backward pass.
- The **shell** is a text interface to the operating system: commands such as `cd`, `ls`, `cat`, `grep`, piped together with `|`. **git** is a version-control system; `git clone` copies a repository with its history, `git log` shows it, `git diff` shows changes.
- An **environment** (`venv`, `uv`, `conda`) is an isolated set of installed packages and a Python version, so one project's dependencies do not break another's. **Jupyter** is a notebook interface mixing code cells, their outputs and prose; cells share one live interpreter state, so execution order matters.
- A **stack trace** is printed when a program fails: the chain of function calls active at the error, innermost last, each with file and line number. Read it bottom-up: the last frame is where the exception was raised, the frames above are how execution got there.
- **HTTP** is the request-response protocol of the web: a client sends a method (`GET`, `POST`), a path and headers; the server returns a status code (200, 404, 500) and a body. **JSON** is a text format for nested data: objects `{"key": value}`, arrays `[...]`, strings, numbers, booleans, `null`; it maps directly onto Python dictionaries and lists. API calls to a model provider are HTTP requests carrying JSON.

## Derivation or exercise, stated in full

Complexity of attention in sequence length; topologically sort a computation graph by hand; clone nanochat, run its tests, trace one stack trace

1. **Complexity of attention.** For a sequence of $n$ tokens with model dimension $d$, attention forms the $n \times n$ matrix $QK^\top$, applies softmax row-wise, and multiplies by $V$ ($n \times d$). Count the floating-point operations and the memory needed for the score matrix as functions of $n$ and $d$, and give both in $O(\cdot)$ notation. State what doubles when $n$ doubles.
2. **Topological sort by hand.** Take the expression $L = (a \cdot b + c)^2 + \tanh(a \cdot b)$. Draw its computation graph (one node per operation, edges from operands to results). Produce a topological order of the nodes, and then write the reverse of that order. Say in one sentence why the reverse order is the one in which gradients must be computed.
3. **Clone and run.** In a terminal: clone the nanochat repository, create a fresh environment, install its dependencies, and run its test suite. Record the commands you used and the test summary line.
4. **Trace one stack trace.** Deliberately introduce an error (for example, pass a wrong-shaped tensor or misspell an attribute) in a small script that imports nanochat's model code, run it, and read the resulting stack trace to the line that raised it. Write three sentences: what failed, in which file and line, and which earlier frame called into it.

Closed-book for parts 1 and 2; documentation allowed for parts 3 and 4.

## Self-check

1. Why does a hash table give constant expected lookup time while a sorted list gives $O(\log n)$ and an unsorted list $O(n)$?
2. Give a three-vertex directed graph with no topological order, and say what property it violates.
3. Two Jupyter cells define `x = 1` and `x = 2`. Running them in the order second, first leaves what value in `x`, and what does that imply about reproducing a notebook's result?

## Common misconceptions

- $O(n^2)$ means the algorithm is slow → it describes growth, not absolute time; for small $n$ an $O(n^2)$ method with small constants can beat an $O(n \log n)$ one.
- A stack trace should be read from the top → the top frame is the program entry point; the bottom frame is where the error occurred. Read upward from the bottom to find the first frame in your own code.
- Installing a package once makes it available everywhere → packages live in an environment; a different environment, or the system Python, will not see it.
