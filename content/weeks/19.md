# Week 19: CS336: attention alternatives

## Why this week

The KV-cache is the memory cost that decides serving economics; GQA, MLA and state-space models exist to shrink it. Reconstructing LLaMA-3 8B's training FLOPs and GPU-hours is the first full report audit; week 25 repeats it on DeepSeek-V4 with reported, derived and unknown separated.

## Objectives

- Write KV-cache size per token as a function of layers, key-value heads, head dimension and dtype, and evaluate it for a given context and batch.
- Reconstruct LLaMA-3 8B's training FLOPs from parameter count and token count, and its GPU-hours from a stated hardware utilization, labelling each input as reported or assumed.
- Explain what a selective state-space model (Mamba) replaces attention with and what it gives up.

## Key ideas

- Per token, the KV-cache stores $2 \times L \times n_{\text{kv}} \times d_{\text{head}}$ values; multiply by bytes per value, context length and batch size for the total. GQA reduces $n_{\text{kv}}$ below the number of query heads; MQA sets it to one.
- Training compute $C \approx 6ND$ (week 18); dividing by achieved FLOP/s per GPU gives GPU-seconds. Achieved FLOP/s is peak times model FLOP utilization (MFU), the number most often unreported; the LLaMA reports give enough to back it out.
- Mamba replaces attention with a time-varying linear recurrence whose parameters depend on the input (selection); inference cost per token is constant in context, training uses a parallel scan. What it cannot do is look up an arbitrary earlier token exactly.

## Derivation or exercise, stated in full

KV-cache size vs GQA groups and context; reconstruct LLaMA-3 8B training FLOPs and GPU-hours

Part 1. Write the KV-cache size in bytes as $S(L, n_{\text{kv}}, d_{\text{head}}, T, B, b)$ with $b$ bytes per element. ## Common misconceptions

- "Parameters dominate serving memory." → At long context and moderate batch the KV-cache exceeds the weights; that is why GQA and MLA exist.
- "GPU-hours in a report measure the model's compute." → They measure compute divided by achieved utilization; two labs with the same FLOPs can report very different GPU-hours.
