# Week 38: Build and run week

## Why this week

The design from week 37 becomes a result. The build is delegated to an agent SDK or a coding agent; your work is the audit: that the splits are the frozen ones, that the metrics compute what the design says, that retries are counted. The reliability memo is the first document in the programme with a falsifiable criterion written before the data were seen, which is the discipline the capstone (weeks 41–44) is built on.

## Objectives

- Produce three running arms (fixed workflow, retrieval-assisted workflow, agent loop) that read the same frozen test set and the same model, with the diff between arms limited to control flow.
- Hand-check at least ten metric computations per arm against the raw outputs and the failure taxonomy.
- Write a reliability memo whose criterion was fixed before the run and state whether the run met it.

## Key ideas

- Delegation does not transfer responsibility: an SDK or coding agent writes the glue; you verify the data path from test file to metric number end to end on a sample.
- Retries are part of the system; a retry that changes the answer is a second attempt and counts against cost per successful task.
- Inspect expresses an evaluation as a dataset, a solver and a scorer; mapping your three arms onto one Inspect task makes the scorer identical across arms, which is the point.
- Logs should let any single metric cell be traced back to the prompt, the retrieved context, the model output and the scorer decision.
- A falsifiable criterion names the metric, the threshold, the direction, and the uncertainty rule under which the comparison counts as resolved.

## Derivation or exercise, stated in full

Assemble with an agent SDK or coding agent; audit splits, metrics, retries; run; Inspect eval; reliability memo with a falsifiable criterion

Build. Using an agent SDK (Claude Agent SDK, OpenAI Agents SDK, LangGraph) or a coding agent, implement the three arms from the week-37 design against the frozen test set. Before running, write the reliability criterion: the metric, the minimum difference between arms that you will call real, and the number of runs per arm.

Audit. (1) Confirm the test set hash matches the frozen one and that no test item appears in any prompt, few-shot example or retrieval index. (2) For ten items per arm, recompute task success, context precision and recall, faithfulness and the retrieval/generation failure label by hand from the raw outputs and compare with the pipeline's values. (3) Count retries per item and confirm they enter cost per successful task.

Run. Execute all arms for the planned number of runs; record cost (tokens, dollars, wall-clock) per arm.

Evaluate. Express the comparison as an Inspect eval with one scorer shared across arms; export the per-item results.

Memo. One page: the criterion as written before the run, the results with uncertainty, whether the criterion was met, the failure taxonomy counts per arm, and what you would change in the design.

- Store the scorer's inputs alongside its output so the hand-check is a lookup, not a reconstruction.
- If the agent arm's cost varies widely across items, report the distribution, not the mean.

## Self-check

1. What three things must be identical across arms for the comparison to be about control flow?
2. How does a retry enter cost per successful task, and what happens to the metric if retries are not counted?
3. State your reliability criterion from memory, including the uncertainty rule.

## Common misconceptions

- "The coding agent built it, so the metrics are what the code says." → The audit is the work; the hand-check of ten items per arm is the minimum evidence that the numbers mean what the design says.
- "Agent arms are more expensive, so the comparison should be at equal call counts." → The comparable quantity is cost per successful task at the fixed abstention policy; equal call counts changes the arms.
- "A memo written after the run can still be falsifiable." → The criterion has to predate the data; otherwise the threshold is fit to the result.
