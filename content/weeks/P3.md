# Week P3: Machine arithmetic and memory hierarchy: IEEE 754, bf16/fp16/fp8, cancellation; caches, bandwidth vs latency; what a GPU is

## Why this week

Training and serving a model are bounded by two numbers, floating-point operations per second and bytes moved per second, and by how many bits each number occupies. Every cost estimate in [weeks 3](/week/3), [9](/week/9), [18–21](/week/18), [26–27](/week/26) and [31](/week/31) is arithmetic on exactly these quantities, and the log-sum-exp identity derived here is what makes softmax and cross-entropy computable at all.

## Objectives

- Decode a floating-point format's bit layout into its range and relative precision, and compare bf16 with fp16 on both.
- State the log-sum-exp identity and explain why the naive computation fails.
- Given FLOP/s, memory bandwidth and a matrix size, compute the compute-bound and memory-bound time estimates and say which binds.

## Key ideas

- **IEEE 754** represents a real number as $(-1)^s \cdot 1.f \cdot 2^{e - \text{bias}}$ with a sign bit $s$, an exponent field $e$ of $E$ bits and a fraction (mantissa) $f$ of $M$ bits. The exponent sets the **range**; the mantissa sets the **relative precision**, about $2^{-M}$. Formats: fp32 ($E=8, M=23$), fp16 ($E=5, M=10$), bf16 ($E=8, M=7$), fp8 variants E4M3 and E5M2.
- Consequence: bf16 has fp32's range with about three significant decimal digits; fp16 has about four digits but overflows above 65504. Which matters depends on whether the quantity is a weight, an activation or a gradient.
- **Rounding error**: each operation returns the nearest representable number, so $x \oplus y = (x+y)(1+\delta)$ with $|\delta| \le u$, the unit roundoff. Decimal fractions such as $0.1$ are not representable in binary, which is where $0.1 + 0.2 \ne 0.3$ comes from.
- **Cancellation**: subtracting two nearly equal numbers loses leading digits; the relative error of the result can be arbitrarily large even though each operand is accurate. This is why variance is not computed as $E[x^2] - E[x]^2$.
- **Log-sum-exp**: for $x \in \mathbb{R}^n$ and $m = \max_i x_i$,
  $$\log \sum_{i=1}^{n} e^{x_i} = m + \log \sum_{i=1}^{n} e^{x_i - m},$$
  and the right-hand side never overflows because every exponent is $\le 0$. Softmax and cross-entropy are computed through this identity.
- **Memory hierarchy**: registers, L1/L2 **caches** (small, fast memory holding recently used data), main memory (DRAM), disk. Each level is roughly an order of magnitude slower and larger. **Latency** is the time to the first byte of a request; **bandwidth** is bytes delivered per second once flowing.
- A **GPU** is a processor with thousands of simple arithmetic units that run the same instruction on many data elements, attached to high-bandwidth memory (HBM). Its peak **FLOP/s** (floating-point operations per second) is far higher than its bandwidth in bytes per second; the ratio, FLOP per byte, is the machine's balance point.
- **Roofline**: an operation needing $F$ flops and $B$ bytes of traffic takes at least $\max(F / \text{FLOP/s},\; B / \text{bandwidth})$. If $F/B$ exceeds the machine's FLOP-per-byte ratio the operation is compute-bound; otherwise it is memory-bound. A matmul of large square matrices is compute-bound; a vector addition is memory-bound.

## Derivation or exercise, stated in full

Why 0.1 + 0.2 ≠ 0.3; derive log-sum-exp; bf16 vs fp16; 4096² fp16 matmul time from FLOP/s and bandwidth

1. **Why $0.1 + 0.2 \ne 0.3$.** Write $0.1$, $0.2$ and $0.3$ as binary fractions (the expansions are periodic), round each to the nearest fp64 value ($M = 52$), add the first two with correct rounding, and show that the rounded sum differs from the rounded $0.3$. State the size of the discrepancy in units of roundoff.
2. **Derive log-sum-exp.** Starting from $\log \sum_i e^{x_i}$, prove the shifted identity above for any shift $c$, explain the choice $c = \max_i x_i$, and show that the gradient of $\mathrm{LSE}(x)$ with respect to $x$ is the softmax vector.
3. **bf16 versus fp16.** From the bit layouts, give the largest finite value, the smallest positive normal value and the unit roundoff of each format. State one quantity in training for which fp16's range is the danger and one for which bf16's precision is the danger.
4. **Matmul time.** For $C = AB$ with $A, B \in \mathbb{R}^{4096 \times 4096}$ in fp16, count the flops ($2n^3$) and the minimum bytes moved (read $A$ and $B$, write $C$, each 2 bytes per entry). Using a stated peak FLOP/s and memory bandwidth for one GPU (take the numbers from the GPU MODE lecture or a vendor datasheet, and cite them), compute both roofline times and say which bound binds.

## Common misconceptions

- Floating-point addition is associative → it is not; $(a + b) + c$ and $a + (b + c)$ can differ, which is why parallel reductions give run-to-run differences.
- bf16 is "less accurate" than fp16 in every respect → bf16 has coarser precision but a far wider range; it avoids the overflow and underflow that force loss scaling in fp16.
- A faster GPU (more FLOP/s) always speeds up a computation proportionally → only if the computation is compute-bound; memory-bound work speeds up only with more bandwidth.
