# Week 27: Gate 2

## Why this week

Gate 2 is the exit test for Phase 2: can you account on paper for every FLOP and byte in a training run, without notes. The derivation here is the fourth of the six closed-book derivations and sets competency rows 5 (attention, transformers, pretraining and data) and 7 (compute, memory, scaling, inference economics). Its result is retested in [week 44](/week/44).

## Objectives

- From memory, write per-device memory for weights, gradients, optimizer state and activations under tensor parallelism of degree $t$ and data parallelism of degree $d$, in named variables.
- From memory, write the FLOPs of one training step and the communication volume of the tensor-parallel and data-parallel collectives it requires.
- Produce a 7B-on-64-GPU budget (memory per device, step time bound, tokens per second, time to a stated token count) with every input stated and every step shown.

## Key ideas

- Fix the variables before computing anything: parameters $N$, layers $L$, model width $h$, sequence length $s$, micro-batch $b$, global batch $B$, bytes per weight $p_w$, bytes per gradient $p_g$, optimizer-state bytes per parameter $p_o$, tensor-parallel degree $t$, data-parallel degree $d$, with $t \cdot d = n_{\text{GPU}}$ unless pipeline parallelism is also used.
- Static memory per device without sharding of optimizer state: $N(p_w + p_g + p_o)/t$; with a sharded optimizer (ZeRO-style) the optimizer and possibly gradient terms divide by $d$ as well. Mixed precision adds a master-weight copy to $p_o$.
- Activation memory scales with $b\, s\, h\, L$ times a constant that depends on what is recomputed; it divides by $t$ for the tensor-sharded activations but attention scores scale with $s^2$ unless a fused kernel avoids materialising them.
- FLOPs per training step $\approx 6 N B s$ plus the attention term; per device divide by $n_{\text{GPU}}$; wall time per step is bounded below by FLOPs per device over achieved FLOP/s, and separately by communication: tensor parallelism all-reduces activations twice per layer per micro-batch, data parallelism all-reduces gradients ($2N p_g$ bytes per step per device in a ring) once per step.
- The step is compute-bound, communication-bound, or memory-limited; the budget must say which, and the answer changes with $t$, $d$ and $b$.
- Tokens per second = $B s / \text{step time}$; time to $D$ tokens follows. Dollar cost needs a stated price per GPU-hour.
- Competency rows are set from this derivation only: what you wrote without notes, not what you can look up.

## Derivation or exercise, stated in full

Closed-book: training-step memory and FLOPs under tensor and data parallelism; 7B on 64 GPUs budget. Competency rows 5 and 7 set

Closed-book, in one sitting, no notes or models. Part 1. State the variables above and derive, in terms of them: (a) per-device memory for weights, gradients, optimizer state and activations under tensor parallelism $t$ and data parallelism $d$, with and without optimizer-state sharding; (b) FLOPs per training step in total and per device; (c) bytes communicated per device per step by the tensor-parallel and data-parallel collectives, naming the collective each uses. State every approximation (which FLOP terms are dropped, whether activation recomputation is on, whether weights are kept in two precisions).

Part 2. Set $N$ to a 7B-class dense transformer with widths and depth you choose and state, $n_{\text{GPU}} = 64$ with a GPU whose HBM size, bandwidth and peak FLOP/s you state, and a training token count $D$ you state. Choose $t$, $d$, $b$ and $B$. Compute per-device memory and check it fits; compute the step time lower bound from compute and from communication and name the binding one; compute tokens per second and the time to $D$ tokens. Then redo the budget for one alternative choice of $(t, d)$ and say which configuration you would pick and why. Record the time taken and whether any step needed a lookup; a looked-up step fails the gate for that part.

## Self-check

1. Doubling $t$ halves which memory terms, leaves which unchanged, and adds which communication?
2. Why can a configuration fit in memory and still be a poor choice? Name the two bounds you compare.
3. What does optimizer-state sharding change in the memory formula, and what does it cost in communication?

## Common misconceptions

- "Memory per device is parameters times bytes per weight" → Optimizer state and gradients are usually larger than the weights; activations can exceed all three at long sequence length.
- "More parallelism always shortens the step" → Each degree adds collective traffic; past the point where communication binds, the step time stops falling.
- "FLOPs per step determine step time" → Only in the compute-bound regime; the budget must check the communication and memory bounds too.
