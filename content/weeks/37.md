# Week 37: Berkeley Agentic AI lectures 1–3 and evaluation lecture

## Why this week

An agent is a policy that calls tools in a loop; the week gives the formal frame (a POMDP) and the engineering components (retrieval, reranking, structured outputs, tool protocols) at lecture level, then has you design the experiment that week 38 runs and week 39 attacks. The design is the deliverable: a comparison whose metric separates retrieval failure from generation failure and whose test set is untouched before the run.

## Objectives

- Write the agent loop as a POMDP with the state, observation, action, transition and reward each named concretely for a tool-using LLM.
- Specify the three-way comparison (fixed workflow, retrieval-assisted workflow, agent loop) on one bounded task with a metric that attributes each failure to retrieval or generation.
- Name the retrieval components (embedding model, chunking, hybrid retrieval, reranking) and the Ragas metrics, and say what each measures.

## Key ideas

- POMDP framing: the environment state (documents, tool results, the world) is not observed; the agent sees a transcript; actions are tool calls or a final answer; the reward is task success at the end. ReAct interleaves reasoning tokens and actions; Reflexion adds a self-critique written into memory between episodes.
- A fixed workflow is a program with LLM calls at fixed positions; the agent loop lets the model choose the next call. The comparison is of control flow, with the model held fixed.
- Retrieval-augmented generation (RAG) stages: chunk, embed, retrieve (dense, sparse, or hybrid), rerank, generate. Context precision and recall score the retrieved set against the reference; faithfulness scores the answer against the retrieved context. Each isolates one stage.
- Cost per successful task, not cost per call, is the comparable number across the three arms; an abstention policy (when the system declines) must be fixed in advance or it becomes a free parameter.

## Common misconceptions

- "An agent is a model." → An agent is a control loop around a model; the model is held fixed across the three arms.
- "Retrieval metrics and answer metrics measure the same thing." → Context recall can be perfect while faithfulness fails, and the reverse; separating them is the point of the design.
